# Postbird 校园邮箱场景手册

> 配套文档：[README](../README.md) · [学生工作与学生社团场景地图](STUDENT-WORK-SCENARIOS.zh-CN.md) · [安全策略](../SECURITY.md) · [中文使用指南](GUIDE.zh-CN.md)

Postbird 把校园邮箱从消息入口升级为行动入口。它读取邮件与本地附件，提取任务和证据，准备沟通内容，并继续生成表格、文档、PPT 与归档文件。

## 一、七类校园身份

### 1. 本科生

常见问题包括通知来源多、作业和考试截止时间密集、附件要求难找、给教师回信有压力，以及实习和升学信息分散。

```text
帮我看看这周有哪些必须完成的事情。
```

Postbird 会完成：

1. 汇总教务处、学院、辅导员与任课教师的通知。
2. 提取作业、考试、竞赛和奖学金截止日期。
3. 检查附件中的提交格式与材料要求。
4. 标出需要回复的教师邮件并准备草稿。
5. 生成按时间排序的本周校园行动清单。

核心价值：几十封通知会变成一张清晰待办清单，每项都保留原邮件和附件依据。

### 2. 研究生

常见问题包括导师意见散落在多个线程、论文和数据版本混乱、投稿与答辩节点密集，以及需要及时得体地回复导师。

```text
导师最近让我修改了什么，帮我整理并起草回复。
```

Postbird 会完成：

1. 汇总完整邮件线程和历史承诺。
2. 对照 Word、PDF、PPT 与表格附件中的批注和版本。
3. 生成论文修改清单并标记截止日期。
4. 识别下次汇报时间和待确认问题。
5. 生成指定语气的回复草稿并展示来源依据。
6. 进入邮件预览，等待用户确认。

核心价值：一封导师邮件可以继续变成修改计划、回复内容和汇报准备。

### 3. 辅导员

常见问题包括通知对象多、材料收集量大、难以判断谁还未提交、催办内容需要个性化，以及学生敏感信息需要谨慎处理。

```text
统计奖学金材料提交情况，提醒还缺材料的学生。
```

Postbird 会完成：

1. 对照学生名单搜索相关邮件和附件。
2. 生成材料齐全、材料不完整、尚未提交名单。
3. 标记每位学生缺少的具体材料。
4. 保留邮件和附件证据，并允许人工校正状态。
5. 生成逐人提醒草稿与完整发送预览。
6. 导出 Excel 汇总和留档文件。

核心价值：从材料收集、统计、催办到汇报形成一条可复核闭环。

### 4. 行政老师

常见问题包括报名和审批依赖人工整理、附件命名不统一、回执反复核对，以及同一份数据要制作多种汇报材料。

```text
整理本次培训报名邮件，生成名单、缺失材料提醒和汇报。
```

Postbird 会完成：

1. 汇总报名邮件并提取姓名、部门、联系方式和项目。
2. 检查缺失字段、重复报名和附件完整性。
3. 统一整理附件并生成来源索引。
4. 输出 Excel 名单与缺失材料提醒草稿。
5. 生成 Word 情况汇报和 PPT 概览。
6. 保存可追溯的邮件依据，便于审计和交接。

核心价值：邮件、附件、表格、文档与汇报一次形成完整成果包。

### 5. 教学老师

常见问题包括学生重复提问、邮件作业难统计、请假和补交容易遗漏，以及课程结束后的归档工作量大。

```text
汇总数据库课程的学生邮件，告诉我需要处理什么。
```

Postbird 会完成：

1. 汇总新作业附件、补交申请、请假邮件和重复问题。
2. 建立作业提交表并标记缺交人员。
3. 为不同问题生成可编辑回复草稿。
4. 展示群发收件人和附件预览。
5. 将课程邮件和附件归入统一目录。

核心价值：教师直接看到待处理事项和班级状态，减少逐封翻阅。

### 6. 教授与课题组负责人

常见问题包括学术邀请、投稿通知、合作请求和学生邮件数量大，长线程难以快速恢复上下文，多个项目节点又容易冲突。

```text
帮我处理最近三天的重要邮件，只保留需要我决策的事情。
```

Postbird 会完成：

1. 过滤普通通知与宣传邮件。
2. 汇总论文、合作、基金和学生邮件的完整线程。
3. 提取需要判断、审批或委派的事项。
4. 标出时间冲突、历史承诺和未解决问题。
5. 为需要回复的邮件准备草稿。
6. 将可委派事项整理为课题组任务清单。

核心价值：教授只处理需要判断的部分，其余整理工作由 Postbird 完成。

### 7. 学生组织与学生工作负责人

常见问题包括招新和活动报名来源分散、重复提交与补件版本难辨、策划审批材料繁多、排班签到容易错漏，以及报销、总结、年审和换届归档集中堆积。

```text
帮我整理校园文化节的报名和活动材料，告诉我现在最需要处理什么。
```

Postbird 会完成：

1. 按活动主题发现报名者，或对照已有名单逐人核验。
2. 合并同一人的重复提交，检查报名表、作品、证明和签字页。
3. 标记材料不全、名单外来件、待确认到场和需要人工复核的记录。
4. 提取策划、场地、宣传、安全、预算和负责人的审批节点。
5. 准备个性化补件与确认通知，并生成完整发送预览。
6. 输出报名台账、活动推进表、Word 总结、PPT 概览和交接归档。

核心价值：一场活动从收报名表到审批、执行、总结与交接，都能沿同一份证据链推进。

完整的十类工作场景、人员分工与能力边界见[学生工作与学生社团场景地图](STUDENT-WORK-SCENARIOS.zh-CN.md)。

## 二、在线 Demo 的完整体验

Demo 首页提供七个身份入口，并预置一组虚构邮箱。访客选择身份后，用一句话启动工作流：

```text
扫描模拟收件箱
        ↓
识别身份和工作目标
        ↓
生成今日简报与行动雷达
        ↓
读取邮件线程和附件
        ↓
生成回复、统计表和交付文件
        ↓
展示发送预览与来源依据
        ↓
等待用户确认下一步
```

在线体验地址：[Postbird Live Demo](https://xplore-lab.github.io/postbird/demo/)

Demo 只使用浏览器内的虚构数据，不连接真实邮箱。辅导员、行政和学生组织场景可以下载模拟 CSV，文档场景可以下载真实 OOXML 示例文件。

## 三、六项校园核心能力

| 能力 | 工具 | 用户得到的结果 |
| --- | --- | --- |
| 今日行动简报 | `office_daily_brief` | 今日重点、到期状态、待回复邮件和复核队列 |
| 完整线程理解 | `office_thread_summary` | 参与者、承诺、问题、决策、附件与时间线 |
| 任务提取 | `office_action_extract` | 从单封邮件、完整线程或粘贴通知中提取行动 |
| 上下文回复 | `office_reply_draft` | 指定语气的待审回复和来源引用 |
| 材料收集跟踪 | `office_collection_track` | 已齐、缺件、未交、免交状态和可导出台账 |
| 附件问答 | `office_attachment_ask` | PDF 页、Word 段落、PPT 页与 Excel 行级证据 |

这些能力会与现有的收件分诊、行动雷达、邮件预览、归档、统计和 Office 生成工具组合。用户始终可以用自然语言描述目标。

## 四、材料收集工作流

`office_collection_track` 面向报名与材料收集任务，例如社团招新、活动报名、奖学金、竞赛作品、培训报名、课程作业、请假材料和课题组周报。roster 模式对照已有名单核验，discover 模式可以从指定邮件主题中发现报名者。

```text
选择已有名单或指定报名主题
        ↓
扫描本地邮件索引
        ↓
按发件邮箱匹配或发现参与者
        ↓
从主题、摘要和附件名识别材料
        ↓
生成 complete / partial / pending 状态
        ↓
标记重复提交和名单外来件
        ↓
人工复核并保留校正
        ↓
导出 CSV 或 XLSX
```

自动识别依赖邮件摘要与附件名，适合先完成大范围核对。涉及签字、盖章、表内字段和图片内容时，应继续调用 `office_attachment_ask` 并进行人工确认。

## 五、线程与附件的证据边界

### 邮件线程

默认模式读取本地索引中的短摘要，无网络请求。需要完整上下文时可选择 full 模式，Postbird 通过只读 IMAP 和 `BODY.PEEK` 读取选定线程，将正文暂存在当前内存中，不扩充本地全文索引。

### 本地附件

| 格式 | 引用粒度 |
| --- | --- |
| PDF | 页码 |
| DOCX | 段落 |
| PPTX | 幻灯片 |
| XLSX | 工作表与行 |
| CSV、TXT、Markdown、JSON、HTML、XML | 行范围 |
| PNG、JPG、WebP 等图片 | 返回本地路径，交给具备视觉能力的本地读取器复核 |

附件文件必须位于指定工作目录。工具不会修改或上传文件，也不会自动执行附件中的链接和指令。

## 六、安全与人工确认

1. 收件连接保持只读，不标已读、不移动、不删除邮件。
2. 完整正文只在用户选择 full 模式时按需读取。
3. 材料台账保留人工状态和备注，重新扫描不会覆盖确认结果。
4. 回复工具只生成草稿，发送仍需先调用 `office_mail_preview`。
5. `office_mail_send` 需要有效预览 ID 与 `confirm: true`。
6. 低置信度判断、图片内容和关键审批结果应由用户复核。
