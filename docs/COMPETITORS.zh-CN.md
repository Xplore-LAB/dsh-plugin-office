# 竞品对比：我们在 AI 邮件工具版图里站在哪

> 调研时间：2026-09-07，信息来自各产品官网、GitHub 仓库与第三方评测（链接随文附）。本文回答一个问题：Postbird 最适合解决哪些工作。

## 一、版图总览：四类玩家

| 类别 | 代表 | 价格 | 邮箱支持 | 数据在哪 | 形态 |
|---|---|---|---|---|---|
| 商业订阅 SaaS | Superhuman / Shortwave / Fyxer / alfred_ | $14~30/月 | Gmail、Outlook 为主 | 厂商云端 | 独立客户端或插件 |
| 国内免费生态 | 网易邮箱大师、QQ 邮箱 AI | 免费（VIP 去广告） | 国内邮箱为主，兼容主流 | 厂商云端 | 手机/桌面 App |
| 开源自托管 Web 应用 | inbox-zero（11.7k star） | 免费（托管版 $18/月） | 仅 Gmail / Microsoft（OAuth） | 自己服务器 | 网页应用 |
| MCP 邮件服务器 | email-mcp、mcp-email-server 等 | 免费 | 任意 IMAP/SMTP | 本机 | 给 Agent 供工具 |

## 二、逐类细看

### 1. 商业订阅 SaaS：能力最强，但墙也最高

| 产品 | 价格 | 核心卖点 | 对免费邮箱用户 |
|---|---|---|---|
| [Superhuman](http://cowork.ink/blog/ai-email-assistant) | $30/月（2025 年被 Grammarly 收购） | 键盘流最快客户端，AI 学习你的语气预写回复 | 不支持，无免费档 |
| [Shortwave](https://byteledger.vizleo.com/blog/ai-email-assistants-2026) | 免费档 + $25/月 | AI 原生 Gmail 替身，全收件箱 AI 搜索 | 仅 Gmail，Outlook 都不支持 |
| [Fyxer](https://www.fyxer.com/) | $22.5~46/用户/月 | 邮件 + 会议纪要联动，回复预写 | 不支持，且强制按年付费才有宣传价 |
| alfred_ | $24.99/月 | 夜间自动分诊，早起看日报 | 不支持 |
| SaneBox | $4~7/月 | 任意 IMAP 都能用，只做过滤分诊 | **唯一能连 QQ/163 的商业产品**，但没有 AI 草稿、没有回复能力 |

**结论**：这类产品做的是「职场高预算用户的效率升级」，$14~30/月的墙直接把学生和免费邮箱用户挡在外面。SaneBox 虽然通吃 IMAP，但功能停留在十年前的邮件过滤。

### 2. 国内免费生态：免费且顺手，但天花板明显

[网易邮箱大师](https://sj.qq.com/appdetail/com.netease.mail)（2026 年仍在活跃更新）的 AI 助理已覆盖：智能写邮件、润色续写、总结提炼、快速回复、推广邮件自动聚合。QQ 邮箱 AI 与微信联动、支持批量回复和自动归档。

**它们挡不住我们的地方**：

- AI 处理在厂商云端完成，邮件内容必须交给服务器
- 能力边界由厂商划定：没有求职台账、没有换届归档导出、没有「把附件批量收下来」这类批量动作
- 无法和文档能力联动（导出的东西没法直接接着统计）

**它们比我们强的地方**（诚实）：移动端体验、微信联动、对小白零门槛。非技术用户选它们更合理。

### 3. inbox-zero：开源阵营的标杆，也是最有意思的对照

[elie222/inbox-zero](https://github.com/elie222/inbox-zero)，11.7k star，功能面和我们高度重叠：AI 分类、预写回复、批量退订、冷邮件拦截、邮件分析。

**关键差异在门口**：它只支持 Gmail 和 Microsoft 账号，登录必须走 Google Cloud / Azure 的 OAuth。自托管要 Docker + Postgres + Redis + 自建 OAuth 应用，官方教程明确写着「必须在 Google Cloud 项目里启用 Gmail API 否则登录失败」。

也就是说，**它把中国免费邮箱用户整个排除在了门外**：QQ/163/126 既不在支持列表里，授权码这条路也走不通。而它的托管版收费 $18/月，商业模式又回到了 SaaS 那堵墙。

### 4. MCP 邮件服务器：同一赛道，两种哲学

| 项目 | 工具数 | 特点 | QQ/163 |
|---|---|---|---|
| [codefuturist/email-mcp](https://github.com/codefuturist/email-mcp) | 47 | 最全：多账户、定时发信、IMAP IDLE 实时监听、AI 分诊 | 支持（IMAP） |
| [imap-smtp-email-mcp](https://npmjs.com/package/imap-smtp-email-mcp) | 15 | 文档里明确列出 QQ/163/126/188 的服务器配置 | 支持 |
| [ai-zerolab/mcp-email-server](https://www.corpusiq.io/docs/hermes/mcp/servers/external/mcp-email-server) | 9 | 最小可用，281 star | 支持（IMAP） |
| koda-email（Rust） | 3 | 编译进 koda agent，极简 | 支持（IMAP） |

**哲学差异**：它们提供的是**原语**（读、搜、发、移动、删除、标记），让 LLM 自由组合。听起来灵活，代价是把 `delete_email`、`mark_read` 这类不可逆操作直接暴露给模型，护栏全靠模型自觉。

**我们提供的是场景闭环**：分诊自带判定证据、发信强制两阶段确认、收件严格只读（连删除工具都不存在）、台账只前进不降级、清理只出主意。这些是设计约束，配置改不掉。

另外它们都不带文档侧能力，归档导出的 CSV 还得用户自己找工具接着处理。

## 四、优势清单（可对外讲的）

1. **免费邮箱一视同仁**：QQ/163/126 授权码即用，服务器自动推导。整个开源阵营里，inbox-zero 这个体量的对手明确不支持，MCP 服务器们支持但不管体验
2. **数据全程本机**：与 inbox-zero 自托管同级，优于全部 SaaS 和国内 App
3. **护栏是结构性的**：没有删除工具、收件只读、发信两阶段。MCP 竞品把 delete 直接交给模型
4. **分诊可解释**：每条判定附证据，分错了看得见。AI 黑盒分诊是全行业通病
5. **七类校园身份**：本科生、研究生、辅导员、行政老师、教学老师、教授和学生组织都有可直接体验的工作流
6. **材料追踪可闭环**：已有名单可以逐人核验，开放报名可以按主题发现人员，再生成缺件、重复提交、名单外来件、提醒预览、Excel 和汇报文件
7. **邮件与文档一体**：导出的 CSV 可以继续统计，邮件内容可以继续生成 Word 与 PPT
8. **部署极轻**：一条安装命令完成依赖与 DSH 注册，在线 Demo 无需安装

## 五、劣势与差距（诚实清单）

1. **无实时监听**：email-mcp 有 IMAP IDLE 与桌面通知，Postbird 当前按需拉取
2. **单账户**：多邮箱统一管理仍待实现
3. **生态绑定 DSH**：MCP 竞品可以接入多种客户端，Postbird 当前专注 DeepSeek Harness
4. **真实邮箱管理界面有限**：在线 Demo 使用虚构数据，移动端和常驻桌面客户端仍由现有邮箱产品占优
5. **规则提取仍需复核**：相对日期、签字盖章和图片附件可能需要人工确认
6. **社区规模处于早期**：公开传播应以真实体验、测试和安全边界作为证据

## 六、一句话定位

**「免费邮箱 + 数据本地 + 场景闭环」三个条件同时满足的格子，目前版图里是空的**：SaaS 有本地无免费邮箱，inbox-zero 有开源无免费邮箱，MCP 服务器有免费邮箱无护栏，国内 App 有免费邮箱无本地。我们占的就是这个交集，目标人群（师生、求职者、数据主权人群）恰好全部落在这个交集里。

宣传口径建议：不比「功能最多」（比不过 email-mcp 的 47 工具），不比「体验最快」（比不过 Superhuman），只讲「你的 QQ 邮箱、你的电脑、说句话就办完、还不许 AI 乱来」。
