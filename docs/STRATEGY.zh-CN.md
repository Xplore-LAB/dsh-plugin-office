# dsh-plugin-office 发展策略：邮件深挖路线与巨头壁垒下的差异化生存

> 版本：v1.0（2026-09-04）
> 定位：本文回答三个问题：邮件方向还有什么进一步的空间；巨头生态壁垒长什么样、裂缝在哪里；下一步具体怎么做。
> 数据均来自联网调研，来源链接附于各节。本文档随仓库公开发布，作为项目的定位声明与路线图依据。

---

## 一、格局：巨头的壁垒到底长什么样

### 1.1 国际侧：微软 Copilot 的护城河与三条边界

2026 年 Microsoft 365 Copilot 商业版定价 $18/用户/月（促销价，2026-06-30 后恢复 $21），企业版 $30/用户/月，教育版 $18/用户/月（[Microsoft Education](https://www.microsoft.com/en-in/education/products/copilot-in-education)）。它的护城河由三层构成：

| 壁垒层 | 具体形态 | 强度 |
|---|---|---|
| 分发位 | Windows 与 Office 预装，企业采购默认勾选 | 极强 |
| 数据生态 | Microsoft Graph 打通邮件、日历、文档、会议、聊天 | 强，但仅限微软资产内部 |
| 迁移成本 | 账号体系、SharePoint、OneDrive 深度绑定 | 强 |

但调研确认了三条清晰的边界（[UseCarly 2026 分析](https://www.usecarly.com/blog/outlook-ai)）：

1. **无事件驱动能力**。Copilot 只在用户打开应用并点击时响应。它不会夜间分诊收件箱、不会跟进四天未回复的询价、不会自动把附件归档到外部系统。事件驱动的代理（event-driven agent）在 Outlook 的助手层里没有这个概念。
2. **生态边界即能力边界**。工作流一旦涉及 Stripe、Notion、非微软工具，Copilot 只能看到相关邮件，看不到系统本身。
3. **价格门槛对个人与师生群体无效**。教育版按机构付费，国内高校几乎没有为全体师生采购 Copilot 的先例；学生个人更不会为一个 $18/月的邮件助手付费。

### 1.2 国内侧：四强格局与「创新资源诅咒」

2026 年国内 AI 办公形成四方格局（[时代周报 2026-08](https://www.toutiao.com/article/7655827752670528010/)、[大河财立方 2026-07](https://app.dahecube.com/nweb/news/20260716/280495n86797db9b92.htm)）：

| 玩家 | 2026 动作 | 核心生态 |
|---|---|---|
| 阿里 | 钉钉「悟空」+ 整合 QoderWork/MuleRun 为千问办公（个人版 98/198 元月费档） | 钉钉组织架构 |
| 字节 | 飞书 3 月跃迁为「AI Agent 原生平台」，aily 常驻联系人列表 | 飞书协同矩阵 |
| 腾讯 | 企微 6 月内测 AI Agent「大圆」 | 企业微信 + 微信生态 |
| 金山 | 灵犀专业版（个人）+ WPS Comate 企业大脑 | WPS 文档底座 |

关键结构性事实（[东方财富财富号分析](https://caifuhao.eastmoney.com/news/20260814122723234551110)）：

- **创新资源诅咒**：巨头 AI 能力高度绑定自家客户端，不敢放手做完全独立的跨应用 Agent，因为那会削弱软件本体的核心价值。WPS 因此「很容易沦为 AI 任务的后置输出容器，丢失最关键的任务发起入口」。
- **付费墙摩擦真实存在**：WPS 灵犀高阶 Agent 任务额外消耗「灵点」，顶配会员也无法覆盖，引发套娃收费投诉与退款诉求。
- **模型成本转嫁**：无自研主力模型的玩家重度依赖外购 Token，商业化定价进退两难。

### 1.3 壁垒的四条结构性裂缝

综合国内外调研，巨头壁垒有四条他们自己无法缝合的裂缝，每条都对应独立工具的生存位：

| 裂缝 | 成因 | 独立工具的机会 |
|---|---|---|
| 无事件驱动代理 | 巨头助手只在应用内响应点击 | 终端 Agent 可以跑定时任务、监听收件、主动跟进 |
| 生态边界 | 数据只在自家 Graph/组织架构内 | 开放协议（SMTP/IMAP/CalDAV）天然跨厂商 |
| 付费墙 | 按用户按月收费，个人与师生被挡在外面 | 开源免费，本地运行 |
| 数据主权 | 云端处理，内容过境第三方 | 本地 Agent 处理，数据不出机器 |

特别要点明邮件赛道的独特性：**邮件是互联网上最后几个巨头锁不住的开放协议资产**。微信与钉钉的消息接口封闭，而 SMTP（Simple Mail Transfer Protocol，简单邮件传输协议）与 IMAP（Internet Message Access Protocol，互联网消息访问协议）是任何人都能接入的开放标准。QQ 邮箱、163、Gmail、Outlook 全部提供授权码接入（[QQ 邮箱官方帮助](https://help.mail.qq.com/detail/0/1087)）。巨头可以垄断客户端，垄断不了协议层。

## 二、邮件还有什么搞头

当前套件只覆盖「发」（mail merge）。三个方向按调研价值排序如下。

### 2.1 P0：收件分诊闭环（office_inbox）

**定位**：IMAP 收件、LLM（Large Language Model，大语言模型）分诊摘要、回复草稿，与现有发送闭环成「收发一体」。

调研依据：

- Copilot 在 Outlook 里「读邮件、摘要长线程、提炼优先级」是其用户留存最高的能力（[UseCarly](https://www.usecarly.com/blog/outlook-ai)），证明该场景价值成立。
- 但 Copilot 无事件驱动能力，收件分诊只能被动进行。终端 Agent 可以做 Copilot 做不到的事：每天早上七点自动分诊未读邮件，按「必须回复 / 待办 / 通知 / 可忽略」四分类输出摘要，等待用户一句话确认后批量生成回复草稿。
- 与发送侧的协同是独有优势：分诊出的「必须回复」类邮件可直接进入 `office_mail_preview` 的草稿管线，形成「读、分诊、回」完整闭环，Copilot 与国内四强均无此形态。

设计约束：默认只读（IMAP fetch 不动已读状态），生成草稿而非直发，保持套件一贯的两阶段确认安全模型。

### 2.2 P1：营销自动化深挖（轻量场景级）

**定位**：打开跟踪、退订链接、定时分批、A/B 文案，服务学生组织与小型机构的批量触达。

先说清楚赛道格局，避免正面撞车。自托管邮件营销已是成熟开源领域（[Use Apify 2026 综述](https://use-apify.com/blog/mailchimp-alternatives-2026)）：

| 工具 | Star | 许可证 | 生态位 |
|---|---|---|---|
| Listmonk | ~19.3k | AGPLv3 | 自托管新闻通讯，单二进制 + PostgreSQL |
| Billionmail | ~14.6k | AGPLv3 | 自带 SMTP 基础设施 |
| Mautic | ~9.5k | GPLv3 | 完整营销自动化（线索评分、漏斗） |

这三者都需要 VPS 与数据库，面向运维型用户，且都不是 AI Agent 原生形态。本插件的差异化在**场景级轻量**：学生组织发 500 封纳新通知，不需要也不应该部署一套 Listmonk。合理的能力边界：

- 打开跟踪：正文嵌入 1x1 跟踪像素 + 本地记录（需用户自架回调地址，默认关闭并明示隐私影响）
- 退订链接：每封邮件自动注入 List-Unsubscribe 头与页脚链接
- 定时分批：按 CSV 分批排队，避开单小时发送限额（QQ 邮箱对个人号有严格频控）
- A/B 文案：同一收件人群随机分两组模板，回复率对比

明确不做：线索评分、营销漏斗、落地页。那是 Mautic 的领地，做了就是给自己挖坑。

### 2.3 P2：生态联动扩展

邮件 + 日历 + 联系人的联动。最有性价比的一个切口是 **ICS 日历邀请**：`office_docgen` 或 `office_mail_send` 支持附带 ICS（iCalendar，日历数据交换格式）附件，社团活动通知邮件一键变成「可加入日历」。联系人管理（从收件箱自动沉淀通讯录 CSV）依赖 office_inbox 先落地，顺位靠后。

### 2.4 优先级矩阵

| 方向 | 用户价值 | 实现成本 | 差异化程度 | 优先级 |
|---|---|---|---|---|
| 收件分诊 office_inbox | 高（Copilot 验证过的留存场景 + 事件驱动独占） | 中（imapflow，需用户 IMAP 凭据） | 高 | P0 |
| 退订 + 定时分批 | 中（合规刚需，QQ 邮箱频控现实约束） | 低 | 中 | P1 |
| 打开跟踪 | 中低（隐私敏感，学生场景价值有限） | 中 | 低 | P2 |
| ICS 日历邀请 | 中（活动通知场景高频） | 低 | 中 | P2 |
| 线索评分/漏斗 | 低 | 高 | 无（撞 Mautic） | 不做 |

## 三、目标人群：师生 + 数据主权人群

### 3.1 为什么是师生

调研与自身经验交叉验证的判断：师生是国内最典型的大规模「办公刚需但无生态归属」人群。

- **邮箱生态现实**：学生与高校教师的主力邮箱是 QQ 邮箱、163、教育邮箱，全部开放 SMTP/IMAP 授权码（各校邮件系统基本也走标准协议）。没有 M365 Copilot 的付费通路，飞书钉钉 WPS 的 AI 能力又基本不覆盖邮件场景。
- **批量触达场景清单**（每条都对应本套件现有工具的直接映射）：

| 场景 | 用到的工具 |
|---|---|
| 学生会/社团纳新通知（按报名表个性化） | mail_preview/send + sheet 筛选 |
| 辅导员批量发奖学金/评奖通知（每人附件不同） | mail 逐行附件 |
| 课题组周报催收与汇总提醒 | inbox 分诊 + 定时任务 |
| 导师批量推荐信发送 | template 注入 + mail |
| 求职季海投与面试通知跟进 | inbox 分诊 + 跟进提醒 |
| 校友联络与活动邀请 | mail + ICS 日历附件 |

- **开发者本人的天然优势**：擅长学生工作，意味着场景理解、内测用户、口碑传播渠道三者齐备。这是绝大多数开源作者不具备的冷启动条件。

### 3.2 为什么是数据主权人群

不想受生态连累的办公人群（隐私敏感职业者、律师、研究者、外企外协人员）的共性诉求：内容不过境、文件不出本机、随时可迁移。终端 Agent + 本地文件 + 开放协议恰好三个全中。WPS 套娃收费争议与 Copilot 的数据边界问题，持续为这个人群输送新用户。

### 3.3 定位陈述

一句话版本（放 README 与仓库 About）：

> 面向师生与数据主权人群的终端 AI 办公套件：邮件收发闭环、批量文档生成、表格流水线。本地运行，开放协议，免费开源，不进任何生态的墙。

## 四、竞争策略：独立工具如何在巨头壁垒下生存

### 4.1 五条原则

1. **只做巨头结构性做不了的事**：事件驱动（定时分诊、跟进提醒）、跨生态（开放协议通吃 QQ/163/Gmail/Outlook）、零门槛（免费 + 无部署）。巨头做这些会伤及本体商业根基，这是他们的死穴而非选择。
2. **卡生态缝隙而非攻堡垒**：OfficeCLI（29.7k star）已占「文件级 Office 操作原语」位，Listmonk 已占「自托管营销平台」位。本项目的位是「场景级闭环」：一句话完成一个完整办公任务，不让用户拼装原语。
3. **借 DSH 的终端 Agent 属性**：办公场景里真正稀缺的是「能挂后台跑事件的助手」。DSH 的定时任务与插件体系是这个能力的载体，也是网页版巨头 AI 短期追不上的形态。
4. **把学生工作经验产品化**：纳新、评奖、周报、推荐信这些场景写进 README 示例与文档，做成「开箱即用的师生场景配方」。场景配方是文档成本，却是搜索流量的入口与口碑的抓手。
5. **隐私即卖点**：本地处理、审计日志、两阶段确认、默认只读。这套安全模型在巨头那里做不到（云端推理必然过境），在营销平台那里没人做。

### 4.2 与开源赛道的关系

不与任何人争夺现有生态位，关系图如下：

| 对象 | 关系 | 说明 |
|---|---|---|
| OfficeCLI | 错位 | 它做文件原语，本项目做场景闭环 |
| Listmonk / Mautic | 错位 | 它们是平台，本项目是 Agent 工具；重度营销用户应迁移到它们 |
| M365 Copilot / WPS / 飞书钉钉 | 补位 | 服务它们够不着的人群：不付费、不进生态、要数据主权 |
| DSH 生态 | 共生 | 本项目是 DSH 的办公能力供给方，DSH 是事件驱动的运行时 |

### 4.3 安全模型：把护栏做成卖点

对目标人群而言，安全不是工程细节，是购买理由。本套件的安全叙事分两层讲。

**第一层：数据路径对比（对外传播的主叙事）**

| 环节 | 巨头云端方案 | 本套件 |
|---|---|---|
| 邮件内容、收件人名单 | 上传云端，由厂商模型推理 | 全程本机，LLM 只在本地 Agent 内接触 |
| 文档与表格 | 存厂商网盘 | 留在本机磁盘 |
| 发送凭据 | OAuth 授权给第三方应用 | SMTP 授权码只进环境变量，不落配置文件 |
| 审计 | 无（用户不可见） | 逐封投递 JSONL 日志，可自查可归档 |

这张表对数据主权人群是决定性的：律师发律师函、导师发推荐信、辅导员发评奖材料，内容敏感度都不允许过第三方云。

**第二层：工程护栏（对技术受众与安全审查者的证据）**

成文于仓库根目录的 SECURITY.md，含威胁模型与漏洞史。核心机制：

- 不可信数据驱动的路径（附件列、图片路径）强制限制在工作目录内，堵死「CSV 单元格外泄 ~/.ssh/id_rsa」类攻击
- 邮件头 CRLF 注入清洗（表格单元格无法伪造 Bcc 等头）
- 两阶段发送 + 预览 TTL + 默认草稿模式，Agent 误操作有摩擦力
- 24 小时滚动发送上限、单批上限、节流、域名白名单、收件人去重，五重滥用护栏
- 46 项端到端测试中 9 项是专项安全用例（路径逃逸、头注入、白名单、发送上限）

v1.1.1 主动修复并披露了三个漏洞（附件路径逃逸、图片路径逃逸、邮件头注入）。公开漏洞史反而增强可信度：说明作者会认真做安全审查，而不是从未审视过自己的代码。

**安全叙事的边界**：不宣称「比微软更安全」。微软的企业安全是合规认证栈（SOC 2、ISO 27001），本套件不在这个维度竞争。准确的表述是：**威胁面不同。云端方案的威胁面在数据传输与服务商，本套件的威胁面在本机（磁盘上的凭据、Agent 本身的可信度），且全部威胁面都在用户自己的控制范围内。**

## 五、落地路线图

### 5.0 已完成：v1.1.1（安全加固）

- 修复三处漏洞：附件路径逃逸（高危）、pptx 图片路径逃逸（高危）、邮件头 CRLF 注入（中危），详见 SECURITY.md 漏洞史
- 新增四重护栏：24h 滚动发送上限（dailySendCap，默认 200）、域名白名单（allowDomains）、收件人去重、邮件头清洗
- 测试从 37 项扩至 46 项，新增 9 项专项安全用例

### 5.1 近期：v1.2（office_inbox 收件分诊）

- `office_inbox_fetch`：IMAP 拉取（imapflow），按时间窗口与文件夹过滤，默认只读
- `office_inbox_triage`：交给 DSH 的 LLM 分诊四分类，输出结构化摘要表
- 回复草稿直接对接现有 `office_mail_preview` 管线
- 阻塞项：需要真实邮箱 IMAP 授权码做端到端验证
- 配套：师生场景配方文档（纳新通知、评奖通知、周报催收三篇）

### 5.2 中期：v1.3（营销合规与定时触达）

- 退订链接自动注入 + List-Unsubscribe 头
- 定时分批发送（适配 QQ/163 频控）
- DSH 定时任务配方：每日晨间分诊、每周提醒汇总

### 5.3 长期：v2.0（生态联动）

- ICS 日历邀请
- 联系人沉淀
- 视用户反馈决定是否扩展

### 5.4 推广动作

- 知乎/掘金/CSDN 各发一篇「学生干部如何用 AI 一小时发完 800 封个性化纳新通知」实测文（场景配方即素材）
- DSH 官方插件目录提交（若存在）与 awesome-deepseek-harness 类清单收录
- GitHub topics 补 student-organizations、campus 等检索词

## 六、风险与边界

| 风险 | 应对 |
|---|---|
| DSH 用户基数小，天花板低 | 插件架构与 DSH 解耦层保持薄，核心工具函数可迁移到其他 Agent 框架或 MCP server 形态 |
| QQ/163 收紧 SMTP 频控 | 文档明示各家限额，分批节流默认保守值 |
| 打开跟踪引发隐私争议 | 默认关闭，开启前强制明示；目标人群（师生）场景价值低，可能长期搁置 |
| 巨头补齐事件驱动能力 | 概率低（创新资源诅咒短期无解）；即便发生，本地与免费优势仍在 |
| 个人精力有限 | 严格守住「场景级闭环」边界，拒绝平台化需求 |
